# Landmark selection and scene eligibility

The product starts with the place **the user wants**, not a catalogue of bundled landmarks. The [landmark-selection ComfyUI canvas](../examples/landmark_selection_comfy.json) has two interactive steps: search by name, then choose one numbered result and a coverage radius. The selected `GEOBLOCK_PLACE` value records a display name, coordinates, OSM feature ID when present, feature type, search provider, and requested radius. This is a location choice, **not** a 3D model or shot approval.

Search currently uses [Photon's search API](https://github.com/komoot/photon/blob/master/docs/api-v1.md), backed by OpenStreetMap. It is invoked only when the user queues the node, returns at most five matches, and caches identical requests under ignored `data/landmark_search_cache/`. The visible report includes candidate coordinates and feature types so the user can distinguish similarly named places. [Photon's public server](https://github.com/komoot/photon#demo-server) is suitable for a small prototype, with no availability guarantee or high-volume allowance. Set `GEOBLOCK_PHOTON_URL` to another Photon `/api` endpoint for a dedicated deployment. OpenStreetMap attribution appears in the search report; see the [ODbL terms](https://www.openstreetmap.org/copyright).

The next scene stage must discover eligible data **after** the place is selected. It should show the available terrain/mesh providers intersecting the selected area, licensing and acquisition dates, native resolution/LoD, vertical reference, and actual coverage of the intended camera corridor. A natural-landform shot requires measured relief at the target. An architecture-led shot requires target and visible-building shapes (validated mesh or suitable LoD2+), not just bare-earth terrain, aerial imagery, footprints, or height-only extrusions. No provider should be marked usable from a catalog listing alone; the actual target tile and visible geometry must pass validation. Until then, the generic canvas stops after landmark selection and reports 3D status as unchecked.

The Worm's Head and Woodside Library assets remain **development fixtures** in separate example canvases. They demonstrate terrain compilation, camera blocking, reference assembly and H3 tests, but they are not a list that users must choose from. The legacy fixture resolver and scene loader stay isolated from the new landmark selection flow so an unrelated prepared scene cannot be substituted for the user's chosen place.
